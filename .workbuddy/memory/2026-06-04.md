### Next.js Image priority+loading 冲突修复 (经历 5 次迭代)
- **根因**: Next.js `get-img-props.js:390` 检查 `if (priority && loading === 'lazy')` throw error
- **失败方案 1-3**: `loading={priority ? undefined : loading}` / 条件展开 `{...(!priority ? { loading } : {})}` / `loading={priority ? undefined : loading}` — 均无效
- **失败方案 4**: IIFE 构建 props 对象 `{...(p as any)}` — 仍无效（疑似 Turbopack HMR 缓存）
- **最终方案 5**:
  - `OptimizedImage.tsx`: 完全移除 `loading` prop（从接口和解构中删除），不传 `loading` 给 `<Image>`。由 IntersectionObserver 自行控制懒加载，`priority` 图片不传 `loading`，非 `priority` 图片 Next.js 默认 `loading='lazy'`（第 269 行 `typeof loading === 'undefined'` 时仍走 lazy 逻辑）
  - `ClientHeroSection.tsx`: 直接写 `loading={index !== 0 ? "lazy" : undefined}`，确保 `priority=true` 时 `loading=undefined`，`priority=false` 时 `loading='lazy'`
  - 清除 Turbopack HMR 缓存 `.next/dev`
